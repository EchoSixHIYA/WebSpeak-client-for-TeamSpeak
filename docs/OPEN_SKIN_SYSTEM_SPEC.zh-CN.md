# 更开放的皮肤系统规格

状态：实现规格 0.2；R0–R2 的 schema v2 声明式布局已实现，R3 扩展沙箱仍为默认关闭的开发原型。配套阶段与未完成项见[路线图](./OPEN_SKIN_SYSTEM_ROADMAP.zh-CN.md)。

## 1. 范围

本规格针对 WebSpeak 公开客户端页面：连接首页、语音工作区及公开演示页面。管理员后台 /admin/** 明确排除，不读取皮肤布局、样式或插件配置。

目标是让页面组件可以自由组合和个性化，同时保留 WebSpeak 对基础组件、状态和行为的所有权。长期目标可以支持第三方扩展组件，但组件扩展必须处于受限沙箱中。

当前实现范围：

- 为公开页面登记稳定组件 ID，并在服务端和客户端共同校验布局数据。
- 支持不运行作者代码的皮肤布局能力和本地用户覆盖。
- 保留 v1 视觉皮肤兼容；v2 只接受 `layout-skin` 且 `permissions` 必须为空。
- 为后续扩展 API 和商城定义安全前提。

明确不在本轮范围：

- 皮肤商城、公共目录运营和管理员面板重做；它们在后续阶段一起规划交付。
- 将管理员面板开放给皮肤。
- 在公开页面执行任意 HTML、Vue 模板、JavaScript、WebAssembly 或远程脚本。
- 允许皮肤读取或控制 TeamSpeak 私钥、凭据、服务器配置、管理 API、原始音频流或屏幕流。
- 引入付费托管、CDN、域名或新的服务器费用。

## 2. 核心术语与不变量

**宿主**指 WebSpeak 本身，包括组件注册表、页面结构、状态管理、权限判断和受信任的系统控件。

**基础组件**指 WebSpeak 提供并负责维护的组件。它们始终存在于应用组件注册表中，不能被皮肤删除、替换成作者代码或改写行为。皮肤可提供默认布局，用户可调整其显示、位置、尺寸和样式。即使用户把基础组件从当前布局隐藏，也必须能从不受皮肤控制的恢复入口重新显示或恢复默认布局。

**布局皮肤**指由清单、布局 JSON、受限样式和本地素材组成的声明式包。它不运行作者脚本，不因安装而取得应用数据权限。

**扩展插件**指未来可能提供自定义展示或能力的独立代码包。插件与布局皮肤分开授权、分开运行；安装一个布局皮肤不能隐式安装或启用插件代码。

以下不变量必须成立：

1. 皮肤故障不能断开语音、改变 TeamSpeak 权限、启动麦克风或屏幕共享，也不能绕过宿主确认流程。
2. 组件的业务逻辑、事件监听和 TeamSpeak 命令始终由 WebSpeak 实现。布局只能请求显示宿主注册组件，不能提供一套替代逻辑。
3. 用户始终能退出当前布局、恢复默认布局和撤销插件权限；这些恢复控件不受皮肤布局和样式控制。
4. 权限提示、身份/私钥安全提示、连接安全状态和管理员入口属于宿主可信 UI，不由皮肤绘制、覆盖或拦截。
5. 新格式按未知即拒绝处理；只有宿主版本支持的组件、布局节点、令牌和权限才能生效。

## 3. 组件注册表

每个公开组件由宿主登记稳定 ID 和受控元数据，至少包含：

- id、用户可读名称、所属页面和用途。
- 分类：core、optional 或 trusted-chrome。
- 可用父容器/插槽、允许的布局模式和尺寸范围。
- 可公开调整的外观令牌及其值类型/范围。
- 可展示的数据字段及其敏感级别。
- 键盘操作、焦点规则、无障碍名称和窄屏约束。
- 可触发的宿主动作标识；布局不能任意调用命令。

布局引用 ID，不引用 Vue class、私有 DOM 结构或内部服务名称。未知、已移除或不兼容的 ID 在校验时拒绝，不能降级为任意 HTML。旧 data-ws-part 在迁移期保持为 CSS 兼容钩子，并逐步对应注册表 ID。

trusted-chrome 不属于可布局组件。恢复布局、权限审批、安全提示和管理员导航由宿主独立渲染。基础组件可在用户布局中隐藏，但不从注册表和编辑器中删除；每次应用重启后，宿主仍能通过固定恢复入口找回。

## 4. 布局与外观模型

### 4.1 声明式布局

布局由宿主解释为组件树。节点仅允许引用注册组件和受支持的容器类型，例如 stack、grid、dock、overlay；不允许嵌入 HTML 字符串、事件代码、表达式求值或动态模块。

布局可以为每个组件指定：

- visible：默认是否显示。
- order、group：排列和分组。
- placement：所在区域或相对于父容器的位置。
- size：受组件约束的宽高或尺寸等级。
- style：注册表允许的外观令牌。

为实现自由摆放，可提供容器相对的锚点/比例坐标以及可选重叠层；不能让作者直接注入 position: fixed 等任意 CSS 几何规则。编辑器应展示碰撞、越界、文字遮挡和小屏溢出检查，并允许用户选择忽略非关键提示。

### 4.2 响应式布局

布局包可为桌面、平板、手机声明不同配置，并可指定合理的宿主断点。小屏布局不能仅靠缩放桌面坐标推导。组件移动、尺寸与显隐设置按当前布局配置保存；切换设备宽度不得清除用户配置。

布局坐标必须相对于明确容器，并由宿主限制在可用视区内。用户可以有意重叠组件，但必须能从编辑器或恢复入口解除遮挡。恢复入口和可信系统控件不参加用户坐标变换。

### 4.3 用户配置与作者默认值

皮肤包只提供作者默认布局。用户编辑产生本地覆盖层，按皮肤 ID、布局 schema 版本、页面和设备配置隔离保存。加载作者新版时，不得静默覆盖用户布局；只迁移仍匹配的组件与属性，并保留可恢复的旧配置或提示迁移失败。

用户配置应能导出/导入为数据文件。导入时重新验证组件、坐标、尺寸、样式令牌和限制，不能因为文件来自本地就跳过校验。

### 4.4 样式

几何布局、显隐和排序以结构化布局字段表达；颜色、背景、字体、圆角、阴影和受限动效以注册令牌或作用域 CSS 表达。优先使用组件令牌，避免让所有皮肤依赖实现细节选择器。

视觉 CSS 继续限制在公开皮肤根节点和稳定钩子内；只能引用包内素材。解析器应逐步采用属性/值白名单、函数与选择器限制、复杂度配额，而不是依赖不断扩大的黑名单。布局引擎负责位置和命中区域，因此样式 CSS 不能覆盖布局几何、焦点、可交互区域或可信 UI。

## 5. 包格式与兼容

新包必须使用独立 schema 版本，并声明包类型。布局皮肤与扩展插件必须可分别验证和安装。字段示意如下，最终字段名由 R1/R2 实现评审固定：

    {
      "schemaVersion": 2,
      "packageType": "layout-skin",
      "id": "author.example-layout",
      "version": "1.0.0",
      "minAppVersion": "0.2.7",
      "entry": "skin.css",
      "layout": "layout.json",
      "permissions": []
    }

布局皮肤不得声明可执行权限；其 `permissions` 必须为空。当前 v2 清单拒绝未定义字段，以免未来能力字段被旧客户端静默忽略。未来插件必须使用独立包类型、API 版本和逐项权限审批，不得复用布局皮肤的信任模型。

当前 schemaVersion 为 1 的 .wskin 保持可安装和可运行。v1 CSS 不会因此取得几何布局权限；迁移到新布局包是显式操作，预览后由用户确认。新包校验失败、最低客户端版本不符或激活超时，保留用户最后可用配置并回退到宿主默认外观。

继续沿用当前归档安全要求：限制压缩包和解压大小、文件数、路径长度与 CSS 复杂度；拒绝路径穿越、重复路径、符号链接、超出白名单的文件类型、远程资源和可执行 CSS。具体上限按当前皮肤开发规范维护并在版本发布时测试。

## 6. 权限与沙箱

### 6.1 权限级别

| 能力 | 布局皮肤 | 未来扩展插件 | 原则 |
| --- | --- | --- | --- |
| 组件摆放、尺寸、显示/隐藏和外观 | 允许 | 允许 | 只能操作注册组件和 schema 允许的令牌；基础组件仍可恢复 |
| 读取静态、非敏感的页面状态 | 无运行代码 | 逐项申请 | 只通过宿主 API；只提供完成该组件所需的最小字段 |
| 频道成员、当前频道、发言状态 | 不适用 | 默认拒绝，按能力单独授权 | 绑定当前会话，断开后立即失效 |
| 频道聊天、私聊、身份资料 | 不适用 | 默认拒绝，分别授权 | 私聊和身份视为高敏数据；不得批量导出 |
| 网络请求 | 仅包内素材 | 默认拒绝 | 需要时由宿主代理并按精确来源授权，不允许插件自行访问任意 URL |
| 插件本地存储 | 无 | 默认关闭或严格配额 | 按插件 ID 隔离；不能读取网页 localStorage、Cookie、IndexedDB 或其他插件数据 |
| 调用宿主动作/TeamSpeak 命令 | 不允许 | 默认拒绝 | 插件只能提交意图；宿主在用户操作和自身策略下决定是否执行 |
| 麦克风、音频轨道、屏幕采集 | 不允许 | 不向插件暴露原始对象 | 延续浏览器和宿主的用户授权；插件不能静默开始、旁听或共享 |
| 私钥、访问令牌、Cookie、管理 API、文件系统 | 不允许 | 永久禁止 | 这些数据和接口不属于插件能力模型 |
| 管理后台和管理数据 | 不允许 | 永久禁止 | /admin/** 与管理 API 不进入插件运行环境 |

能力名称必须精确、可审计，禁止通配符授权。任何权限都默认拒绝；包作者只能声明请求，不能自行授予。用户拒绝某项权限后，插件必须仍能提供不依赖该能力的功能，或清楚说明该功能不可用。

建议的首批权限 ID 为 session.status.read、session.members.read、chat.channel.read、chat.private.read、identity.profile.read、network.fetch 和 storage.private。权限 ID 及其数据字段范围必须由宿主版本化登记；network.fetch 还必须绑定明确来源。不得提供通用的 admin、filesystem、credentials、media.raw 或 teamspeak.command 权限。即使未来存在网络权限，也不得默认把私聊、身份或凭据数据交给网络请求；跨越这两类能力需要单独的风险提示和明确批准。

基础动作组件仍由宿主渲染和处理。用户点击一个宿主提供的麦克风、离开或频道按钮，不等于把对应动作 API 授给皮肤；扩展不能在后台直接调用同一动作。

### 6.2 可信边界

当前皮肤 CSS 在应用文档中加载。根节点作用域、CSS 解析器和路径校验是输入限制，不是浏览器安全沙箱；恶意视觉规则仍可能误导用户或妨碍操作。因此：

- 第一阶段不执行第三方 JavaScript、WebAssembly 或 HTML 模板。
- 权限提示、恢复入口、可信状态和管理 UI 必须脱离可皮肤化根节点渲染。
- 对布局几何、隐显和交互命中区域的控制由宿主布局引擎实现，避免依赖主页面 CSS。
- CSS、文案和图片均视为不可信输入，分别经过 schema、解析器和资源校验。

当前只有开发安全原型，尚未接入皮肤安装流程或公开页面运行时。JavaScript 原型使用不透明源的 sandbox iframe 作为**受信任引导壳**，只授予 `allow-scripts`，不授予 `allow-same-origin`、顶层导航、弹窗、表单提交、下载或媒体权限。作者 JavaScript 在独立 Worker 中执行；Worker 没有 DOM、`window`、网页存储或应用全局对象。Worker 侧隐藏网络、子 Worker、IndexedDB、Cache Storage 和 WebAssembly 等全局，CSP 作为纵深防御拒绝网络、远程脚本、图片、媒体和子框架。此前实测发现目标浏览器没有按预期执行 `navigate-to 'none'`，因此隔离不依赖该指令：不可信代码位于 Worker，不能自行导航壳页面。宿主绑定精确 iframe `WindowProxy`、opaque `null` origin、一次性 nonce 和单一转移端口后改用独占 `MessageChannel`；壳只转发固定格式的能力请求，不接收任意 HTML 或代码作为渲染指令。撤权和关闭会通知壳调用 `Worker.terminate()`，并在短超时后由宿主移除 iframe。这个 JavaScript 原型用于验证隔离与消息协议，因普通 Worker 没有硬内存配额，不可用于生产。

另有一个 Wasm-only 运行原型：扩展包仅提供最多 256 KiB 的 Wasm 二进制，不执行作者 JavaScript。Worker 先做有界预检，最多接受 128 个函数、单个函数体 32 KiB、代码段总计 192 KiB 和 8 个自定义段；类型只接受函数签名和数字标量，每个签名最多 64 个参数/结果值，整个模块最多 4096 个局部值、每个函数最多 256 组。指令扫描拒绝 GC / 引用 / SIMD / 线程类型与指令、start 函数、表元素段和未知扩展指令。作者二进制不会交给浏览器的原生 Wasm 编译器，而由固定版本的 Wasmi 解释器解析与执行；解释器容器本身的 Wasm 线性内存上限为 64 MiB，guest 只能使用一块宿主提供的 `env.memory`，上限 64 页（4 MiB）。运行时只接受可选且经 `session.status.read` 授权的状态读取导入，并只允许一个 `run` 函数导出。Worker 和受信解释器初始化期限为 3 秒；开始运行后，Wasmi 每次最多消耗 10,000,000 fuel，宿主另以 100 毫秒 Worker 看门狗兜底。跨 Worker 消息最多 8 KiB，状态快照最多 512 字节、最多读取 10 次。授权快照由宿主持有，Wasm 只能收到拷贝，不能通过篡改线性内存改写宿主返回值。该原型仍是一次性安全演示，没有 UI 渲染 API、授权界面或产品接入。

解释器容器的 64 MiB Wasm 上限与 guest 的 4 MiB 线性内存上限，能限制作者模块解析和执行期间由 Wasmi 分配的内存；作者字节不会触发浏览器对不可信模块的原生编译开销。浏览器仍没有普通 Worker 的进程级 RSS 配额，因此这不等于限制整个浏览器进程的 RSS，也不能抵御浏览器引擎或受信解释器本身的漏洞。10,000,000 fuel 是执行指令预算；100 毫秒墙钟看门狗是额外的 Worker 终止保护。生产扩展运行时仍保持关闭，直到产品 API、授权 UI、故障恢复流程完成接入并通过独立安全评审。安全页的 19 项用例已在 Chrome for Testing 155.0.8059.39、Edge 和 Codex 内置浏览器通过；这仅确认本机版本，不代表不同操作系统或未来版本均已验收。浏览器用例通过不等于安全审计。

插件不得直接访问宿主 DOM、Vue 实例、全局变量、Cookie、浏览器持久化区、应用请求客户端或 TeamSpeak SDK。宿主通过专用消息通道提供版本化、带 schema 的能力 API。每次请求均按插件 ID、当前会话、已批准能力和用户操作重新判断；校验调用方窗口/消息源、请求大小、频率和数据范围。初始化握手须绑定该 iframe 的 window source 和单次随机 nonce，成功后转交独占的 MessageChannel；不能只依赖 opaque iframe 的 origin 值，也不能通过通配 postMessage、共享对象引用或未校验事件回调授权。

### 6.3 授权生命周期

1. 安装/启用时展示发布者、来源、包版本、完整权限清单和风险级别。
2. 仅声明权限不等于获准。对高敏权限，应在首次使用前单独解释其用途并取得明确同意。
3. 插件版本升级后若权限增加或权限含义变化，必须重新征求同意；用户已有的无关授权不能扩大。
4. 用户撤销权限时，宿主立即拒绝后续调用、停止插件执行并丢弃该权限下的临时数据。
5. 卸载时停止计时器、消息订阅和 UI，删除该插件命名空间内的存储；不改动其他皮肤、插件或 WebSpeak 数据。
6. 权限决定保存在本地；不得为了商城分析而上传用户身份、会话或权限记录。

### 6.4 资源与滥用控制

布局和样式包沿用当前皮肤包体积限制，并为新格式增加节点数、嵌套深度、属性数、动画数和素材总量上限。插件执行环境需设置消息频率、单次消息大小、启动期限和停用/重启上限。

JavaScript 隔离原型限制源码为 64 KiB、单条消息为 8 KiB、最多 10 条 API 请求/秒和 10,000 条总请求；Worker 最多保留 16 条未完成请求。该 JavaScript 执行原型仍因没有硬内存配额而保持关闭。Wasm-only 原型限制二进制为 256 KiB、函数最多 128 个、单函数体最多 32 KiB、代码段最多 192 KiB、自定义段最多 8 个、签名每类值最多 64 个、模块局部值最多 4096 个、每函数最多 256 组；解释器容器最多 64 MiB，guest 线性内存最多 4 MiB，每次运行最多 10,000,000 fuel，并有 3 秒初始化期限和 100 毫秒 Worker 看门狗。跨 Worker 消息最多 8 KiB，状态快照最多 512 字节、最多读取 10 次。预检只接受数字标量和受支持核心指令，拒绝 GC / 引用 / SIMD / 线程、start 函数、表元素段和未知扩展指令。浏览器不提供普通 Worker 的进程级 RSS 配额，因此规格只承诺上述解释器和 guest 边界，不声称能限制浏览器进程 RSS。Wasm 仍为开发原型，接入前须完成独立安全评审和产品生命周期设计。安全测试覆盖高频消息、解释器与 guest 内存边界、fuel 死循环、GC/超大向量声明、函数数量与函数体复杂度、数据范围、伪造握手、未授权能力和撤权终止。

### 6.5 发布者与包信任

包校验值只能说明下载字节与目录记录一致，不能证明作者可信或代码安全。未来商城至少应显示来源、版本、许可证、权限和校验状态；签名可用于验证发布来源，但不能替代沙箱和权限审核。下架或撤销应记录包 ID 与受影响版本，并让客户端在下次可联网时停止建议/更新该版本；离线运行时仍须允许用户卸载或回退。

## 7. 失效、恢复与无障碍

- 布局 JSON 无效、组件不存在、加载超时或插件崩溃时，回退到宿主默认布局；不得阻断连接页或会话恢复。
- 恢复入口始终可通过键盘和触屏操作，提供明确名称、焦点样式和屏幕阅读器标签。
- 布局编辑器必须显示当前焦点顺序与触屏命中区域预览；不能只检查视觉坐标。
- 用户可保存桌面和移动布局；窄屏状态下关键操作至少存在可访问路径。
- reduced-motion 偏好、语言变化、文本扩展和浏览器缩放不能导致安全/恢复 UI 消失。
- 皮肤/插件错误只显示在宿主可信提示区域，并允许一键停用对应包。

当前编辑器的焦点辅助预览按浏览器顺序列出公开页面中可布局的键盘目标，并在宿主层叠加实际命中矩形；小于 44×44 CSS px 的目标以红色显示。注册表约束在默认布局和个人覆盖下都执行。编辑器面板不使用动效，语言随页面 `lang` 变化，焦点列表支持长文本换行，固定恢复入口位于皮肤根节点之外。自定义皮肤加载失败时页面自动回退，并在宿主可信提示层提供记住内置皮肤选择的一键操作；此操作停用当前选择，不会在服务端目录中禁用或删除皮肤包。

## 8. 安全验收清单

每次开放新的布局或权限能力前，至少验证：

- 不存在读取 /admin/**、管理 API、DOM 外部根节点、Cookie、localStorage 或 TeamSpeak 凭据的路径。
- 未授权插件不能联网、读取聊天/身份数据、接收原始音频或启动屏幕采集。
- 权限增加、拒绝、撤销、卸载和更新竞态不留下旧订阅或迟到回调。
- 恢复入口、权限提示、身份安全提示、焦点可见性和基础组件可恢复。
- 未知 schema、权限、组件、文件类型、路径穿越、压缩炸弹、极端嵌套和超大消息均安全失败。
- 布局在五种产品语言、键盘导航、窄屏、触屏和浏览器缩放下仍能使用。
- 新布局能力没有扩大管理员页面或语音服务端的工作范围。
