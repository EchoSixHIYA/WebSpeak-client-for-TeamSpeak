# 更开放的皮肤系统规格

状态：schema v3 声明式开放皮肤已接入公开客户端、浏览器导入和服务端包校验。当前实现的是受限组件树与宿主能力桥，不执行皮肤作者提供的 JavaScript 或 WebAssembly。阶段记录见[路线图](./OPEN_SKIN_SYSTEM_ROADMAP.zh-CN.md)，创作者操作见[皮肤开发规范](./SKIN_DEVELOPMENT.md)。

## 1. 目标与范围

皮肤可以重新排列、设置样式和显隐公开客户端中的元素，并可提供由宿主安全渲染的自定义声明式组件。基础组件始终由 WebSpeak 提供和维护；皮肤可以隐藏当前布局中的基础组件，但不能删除其注册、替换其业务行为或令其永久不可恢复。编辑器恢复入口、权限管理和系统安全提示由宿主放在皮肤作用域之外。

适用页面为连接首页、语音工作区和公开演示页。管理员面板及其数据、管理 API 明确排除，不读取皮肤包。语音服务的运营、广告、陪玩、活动和商店等页面不属于语音客户端皮肤范围。

## 2. 包格式与执行模型

皮肤格式按版本区分：v1 保持视觉皮肤兼容；v2 提供有界布局 JSON；v3 使用 open-skin 清单、受控 CSS 和可选的 components.json。v1/v2 的 CSS 继续拒绝布局类声明，既有用户包不会因升级而获得新权限。v3 才允许 CSS 控制公开页面中的布局、位置、尺寸、顺序、文字排版和显隐。

v3 自定义组件不是脚本插件。宿主解析 JSON 中的元素白名单、受限属性、数据绑定、重复列表、条件和事件声明，再由 Vue 创建安全节点。包不能提交 HTML 字符串、事件处理代码、JavaScript、WebAssembly、远程脚本、任意 URL、表单导航、浏览器存储访问或网络调用。未知字段、元素、动作、数据路径和权限一律拒绝。

每个组件只能声明 home、voice 或 demo 页面中的一个页面、一个有界的树和精确权限清单。components.json 全文不超过 256 KiB；最多 32 个组件；每组件最多 256 个节点、16 层深度、100 个重复行、32 个本地状态值和 24 个宿主动作。图片仅可通过包内 image 资源引用。

## 3. 可读数据和权限

组件权限按组件单独请求，用户在宿主确认界面查看用途后才启用。授权按皮肤 ID、版本、页面、组件和权限策略版本保存；换版本或策略含义变化会重新询问。皮肤设置中的独立入口可查看和撤销授权；拒绝或撤销后对应组件不渲染、不触发动作。

当前公开只读能力如下：

- session.status.read：连接状态、当前频道和显示名称。
- session.channels.read：公开频道树、频道名称、层级、人数和当前频道标志。
- session.members.read：可见成员名称、所在频道、在线状态、说话状态及本人标志。
- chat.channel.read：当前公开文字频道中可见的消息。
- favorites.read：收藏项名称、类型、是否当前项和随机不透明本地令牌；不提供地址或凭据。

当前宿主动作如下：

- voice.joinChannel 需要 session.channel.join，只能请求加入当前页面公开可见的 TeamSpeak 频道，仍经过宿主和原有密码、权限流程。
- favorites.switch 需要 favorites.switch，只能让宿主按不透明令牌选择本机已有收藏并走原连接流程。
- chat.sendMessage 需要 chat.channel.send，只能发送到当前公开文字频道；不包括私聊。
- ui.setState 只修改该组件短暂的本地标量状态，不需要会话权限。

动作仅能绑定到真实可信用户事件。输入和 change 事件不能调用宿主动作；键盘动作仅响应 Enter 或 Space。宿主再次检查当前频道、令牌及动作参数。皮肤不能控制麦克风、音频设备、屏幕采集、身份密钥或 TeamSpeak 管理命令。

数据授权不是数据上传授权：组件没有任意联网或持久化 API，权限决定保存在本机。渲染进程不会把服务器地址、密码、身份私钥、访问令牌、Cookie、私聊、原始音频或屏幕流交给皮肤。

## 4. CSS 与基础组件

全部 CSS 被重写到当前公开皮肤根节点。选择器必须锚定 :root、data-ws-page、data-ws-part 或 v3 的 data-ws-plugin-part；v3 可在这些锚点之外使用皮肤自己的 class 和 ID。禁止全局逃逸、@import、脚本化 CSS 值和外部资源；图片和字体必须打包。不同 skin CSS 变量使用 --skin- 前缀。

v3 CSS 可排列和重设公开 UI，因此可能遮挡麦克风、退出、共享或恢复入口。导入器会对隐藏界面发出提示，但这不是安全边界，也不能证明皮肤布局可用。可信的皮肤选择、恢复入口、组件权限确认和撤销控件在皮肤根节点之外；作者必须在桌面和移动布局中保留必要语音操作的可达路径。用户始终可切回内置皮肤。

皮肤与 /admin/** 完全分离。不得将后台页面标记为公开皮肤页面，也不得通过资源、选择器或组件数据间接读取管理员内容。

## 5. 校验与回退

客户端导入和服务端登记都会校验 manifest、ZIP 路径、组件协议、所引用素材和文件限额。运行时会再次解析持久化的组件文档；无效组件不执行。权限界面和恢复控件由宿主代码渲染。v3 CSS 的结构限制可降低跨应用影响，但 CSS 不是针对恶意脚本的沙箱。

皮肤载入错误不得清除用户布局或 TeamSpeak 会话。组件树为空、权限被拒绝或皮肤无效时，宿主本身和既有功能仍可由用户恢复。管理员后台仍沿用自己的样式和服务端管理流程。

## 6. 商城和预算约束

皮肤商城、公共目录和管理员面板重做不属于本轮实现，按路线图后续规划。未来优先使用公开 GitHub 仓库和 Release 附件等现有免费能力；若免费方案不能满足需求，需重新评估范围，不自动新增托管、CDN、域名或其他费用。公共目录不得包含内部服务器地址、密钥、测试节点或其他隐私数据。

## 7. 后续安全工作

- 扩展数据字段或宿主动作时，增加精确 schema、权限和宿主侧运行时验证，不暴露内部 SDK 对象。
- 对恶意输入、路径别名、拒绝授权、撤销、更新和皮肤切换增加测试；高敏能力必须单独设计。
- 不把当前 v3 声明式包描述为可执行代码沙箱。若未来考虑代码扩展，应另行开展威胁建模、浏览器隔离评估与独立安全审查。
- 商城发布、签名、下架、更新和撤销设计与管理员面板重做一起验收，且保持零新增服务费用为默认约束。
