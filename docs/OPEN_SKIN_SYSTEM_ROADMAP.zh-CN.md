# 更开放的皮肤系统路线图

状态：R0–R2 已在 `skilV2` 分支实现并验收；R3 的 JavaScript / Wasm 安全原型已在本机 Chrome、Edge 和 Codex 内置浏览器通过 19 项测试。Wasm 原型改由固定 Wasmi 解释器处理作者二进制，并为解释器内存与执行 fuel 设置硬上限；生产扩展仍保持关闭，等待产品接入和独立安全评审。浏览器不提供整个进程 RSS 配额，因此不宣称进程级 RSS 上限。商城与管理员面板改造依照用户决定留待后续管理员面板重做。

本文与[更开放的皮肤系统规格](./OPEN_SKIN_SYSTEM_SPEC.zh-CN.md)配套。商城目录和管理员界面改造暂不在本阶段实现，计划在管理员面板重做时一起交付。

## 目标

让公开客户端的页面组件可以由用户选择、摆放、缩放、设定样式和显隐；基础组件继续由 WebSpeak 提供，任何皮肤都不能替换其行为或永久移除它。长期允许第三方扩展提供自定义组件，但扩展必须通过明确的权限边界与沙箱运行。

本路线以安全和可维护为约束：

- 管理后台 /admin/** 不属于皮肤范围。
- 第一阶段只执行受验证的声明式布局和视觉配置，不执行皮肤作者提供的 JavaScript。
- 不因本功能增加付费服务、域名、存储或服务器费用。商城和分发后续优先复用公开仓库及现有免费能力；若免费方案不满足规模要求，不能自动改用付费服务。
- 继续识别当前 schemaVersion 为 1 的 .wskin 包；升级格式时必须有兼容和回退路径。

## 当前基线

当前 .wskin 是 ZIP 包，含 manifest.json、CSS、可选文案和包内素材。运行时校验包大小、路径、CSS 选择器、布局相关属性及资源 URL，再将样式限制在公开皮肤根节点。当前格式不提供组件排列和尺寸控制，不允许运行皮肤脚本；管理员面板使用独立样式。

CSS 作用域与校验可以降低意外影响，但样式仍运行在应用页面中，不能视为抵御恶意代码的完整安全沙箱。下一版布局能力应由宿主解析声明式数据并创建宿主组件，不通过放宽 CSS 黑名单来实现。

当前实例皮肤目录由 WebSpeak 服务端提供，管理员皮肤界面管理实例包。公共商城是独立的目录与发布问题，留到管理员面板重做时确定。

现行格式、控件钩子和限额见[皮肤开发规范](./SKIN_DEVELOPMENT.md)。

## 阶段

### R0：边界与威胁模型（已完成）

- 定义组件注册表、必要组件、可信宿主 UI、布局格式和插件权限。
- 明确声明式皮肤和可执行扩展是两类不同能力。
- 记录管理员后台排除项、零新增预算约束和 v1 兼容策略。

**完成条件：** 规格文档评审完成；任何实现任务都能明确指出影响的组件、权限和回退行为。

### R1：稳定的公开组件注册表（已完成）

- 为公开页面组件分配稳定 ID，并验证所有公开 `data-ws-part` 均已登记；管理员页面不进入注册表。
- 将必要组件、可选组件、可信安全 UI 分开登记。
- 明确组件的键盘操作、焦点顺序、屏幕阅读器名称和窄屏最小尺寸。
- 把目前分散的 data-ws-part 逐步映射到注册表；现有 CSS 钩子在迁移期保持有效。

**已实现并验证：** 226 个公开组件 ID 均有可读名称、用途、分类、页面根容器、可编辑能力、数据敏感级别、键盘/焦点/无障碍策略、窄屏策略、尺寸与触控范围、样式令牌元数据。可信组件的布局模式、样式令牌和容器权限为空；可信祖先中的通用控件也不能绕过保护。模板扫描验证所有公开 `data-ws-part` 均登记，并检查带原生交互语义、键盘操作或拖放能力的钩子具备至少 44px 的触控尺寸和 1 倍最小缩放。布局运行时现在对所有可编辑交互组件始终执行注册表的 44px 最小命中区域，不要求用户先保存布局覆盖。演示页语音卡片已补键盘操作和可见焦点环。服务端与客户端共用相同注册表校验。

### R2：声明式布局与本地自定义（已完成）

- 引入新版本布局清单，以注册表中的组件 ID 描述位置、尺寸、缩放、颜色、显隐和响应式配置。
- 为桌面、平板和手机提供独立布局配置；坐标由宿主限制在有界数值内。
- 提供本地布局编辑、撤销/重做和恢复默认布局的能力。
- 位置、尺寸、显隐由布局配置表达，继续拒绝皮肤 CSS 覆盖几何和交互区域。
- 个人编辑保存在浏览器本地，和皮肤包作者的默认布局分开；支持导入、导出与版本迁移。

**已实现并验证：** schema v2 声明式布局、桌面/平板/手机独立配置、直接拖动和属性编辑、本地撤销/重做、恢复默认、导入/导出；编辑器恢复入口和皮肤加载错误恢复提示都由宿主在皮肤根节点外渲染；v1 视觉皮肤继续受支持。坐标滑块和拖动都按页面根容器边界限制；触控控件不能缩到 44px 以下；编辑器可提示碰撞/溢出，并允许仅对当前布局忽略提示。新增焦点辅助预览：按浏览器顺序编号可布局的键盘控件，叠加实际命中区域并明确标出小于 44×44px 的目标；尺寸由布局运行时在默认状态和自定义布局下共同保证。失败的自定义皮肤会自动回退，并提供可信的一键切换到内置皮肤且记住选择的入口。本地演示页已确认焦点列表与覆盖层正常；测试覆盖焦点顺序算法、默认触控尺寸与 trusted-chrome 排除、皮肤加载失败回退和内置皮肤恢复。布局存储测试覆盖 v1 到当前存储格式迁移、无效项恢复导出、旧键备份及未来格式保护。ILLUSIA 已转换为 v2 布局皮肤并在浏览器中验证样式和包内素材正常加载。

### R3：扩展 API 与权限代理（仅在 R2 稳定后）

- 首先发布无代码的布局和样式能力，不因用户期待插件化而提前执行任意脚本。
- 若要允许扩展代码，先实现隔离运行时、能力权限账本、宿主 API 代理、权限撤销和资源配额。
- 扩展通过版本化消息协议请求能力；宿主逐次校验，而不是把 DOM、浏览器存储、网络或媒体对象直接交给扩展。
- 先以只读、低敏的会话状态能力做原型。私聊、身份、网络、麦克风、屏幕共享和命令执行须独立评审，不随一般 UI 权限自动开放。

**完成条件：** 隔离原型通过针对 DOM 访问、同源访问、未授权网络、消息伪造、恶意高频请求、权限撤销和升级增权的安全测试；不满足时保持禁用可执行扩展。

**当前原型与验收：** JavaScript 原型验证不透明 sandbox iframe、Worker 隔离、精确 `WindowProxy` / `null` origin / 随机 nonce 握手、独占 MessagePort、权限代理、撤权和消息配额。另有 Wasm-only 一次性运行原型：源码最多 256 KiB，预检最多 128 个函数、每个函数体最多 32 KiB、代码段最多 192 KiB、自定义段最多 8 个；函数签名每类值最多 64 个，整个模块的局部值最多 4096 个、每个函数最多 256 组；仅接受数字标量类型和受支持的核心指令，预检拒绝 GC / 引用 / SIMD / 线程类型与指令、start 函数、表元素段及未知扩展指令，以防越过线性内存限制或在执行前造成无界初始化。作者 Wasm 字节不会交给浏览器原生 Wasm 编译器，而是在 Worker 中交给固定版本 Wasmi 解释器解析和执行；解释器自身线性内存最多 64 MiB，获批扩展的宿主 `env.memory` 最多 64 页 / 4 MiB，每次执行最多 10,000,000 fuel。解释器采用 portable-dispatch，避免 wasm32 默认递归分发随每条指令耗尽调用栈。运行时只接受可选的获批状态读取导入，只允许单一 `run` 导出；3 秒期限覆盖 Worker 和解释器初始化，100 毫秒宿主看门狗作为 fuel 之外的后备保护。宿主保留脱敏快照副本，Wasm 无法通过改写线性内存伪造宿主返回值。浏览器安全页的 19 项用例已在 Chrome for Testing 155.0.8059.39、Edge 和 Codex 内置浏览器全部通过，涵盖 DOM/存储/同源/网络/导航隔离、伪造握手、未授权能力、撤权及取消待处理读取、高频请求、4 MiB 内存、fuel 死循环、GC 分配、超大签名/局部/元素向量、状态篡改和 start 函数拒绝。生产运行时仍关闭；原型尚无 UI 渲染 API、授权界面或产品接入。

**完成状态与边界：** R3 的开发原型已满足本阶段完成条件：三种浏览器中的 19 项安全页测试均通过，作者 Wasm 的解析与执行、guest memory、fuel、权限代理和可终止 Worker 均有明确限制。它不构成浏览器进程 RSS 配额，也不覆盖浏览器引擎漏洞；生产扩展保持关闭，直到产品 API、授权 UI、故障恢复流程完成接入并经过独立安全评审。此阶段不引入付费基础设施。

### R4：皮肤商城与管理员面板重做时交付

- 目录、包分发和运行时安装使用平台无关的清单协议。
- 先以人工审查和版本化公开目录发布；支持兼容版本、来源、许可证、校验值、信任标签、下架和撤销记录。
- 商城配置和管理随管理员面板重做设计，但管理后台本身仍不可被皮肤化。
- 默认使用现有公开 GitHub 仓库或经确认的免费静态能力；皮肤包优先作为版本化 Release 附件。不得把内部服务器地址、密钥、测试节点或其他私密配置放入公共目录。
- 暂不承诺评分、评论、自动付款、付费托管或第三方账号接入。

**完成条件：** 用户能查看来源和权限、安装/更新/卸载/回退；管理员能处理下架和撤销；离线或目录不可用时，已安装皮肤可安全回退。

## 迁移与发布策略

- v1 .wskin 继续作为视觉皮肤兼容格式；不得把原有 CSS 静默解释成新的布局权限。
- 新格式使用单独的 schema 版本。未知版本、未知组件、未知权限和超出限额的包必须失败关闭，并提供可理解的错误。
- 新包加载失败、兼容性不符或插件崩溃时，回退到宿主默认布局；用户数据和 TeamSpeak 会话状态不得因皮肤故障丢失。
- 每个阶段单独验收，相关变更合并后统一运行验证；皮肤系统之外的语音、服务器管理或 Android 功能不借此扩展。
