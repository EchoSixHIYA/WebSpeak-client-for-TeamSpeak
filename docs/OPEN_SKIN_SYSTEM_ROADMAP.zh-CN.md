# 更开放的皮肤系统路线图

皮肤只作用于 WebSpeak 的公开连接首页和语音工作区。完成态要求作者能把公开界面几乎完整地做成自己的应用：所有公开组件都能重新排列、换皮、显隐或由作者自定义组件替代；作者可为自定义界面编写布局、样式和本地交互逻辑，不受固定宿主控件目录限制。TeamSpeak 连接、聊天、频道和音频行为仍由宿主能力层执行，管理后台、管理 API、演示设施及 KOOK 运营/广告页面不在范围内。

现有 v1/v2/v3 是兼容基础，不是“万物皆插件”的完成态。v3 的标签/属性、数据路径和宿主动作均为有限白名单；v4 有界 Wasm UI 已在生产构建开放，并保留摘要绑定的本地授权、权限投影和全局 worker 治理。浏览器端到端验证及独立安全审查仍未完成。不得用“支持自定义节点”或“支持整页 surface”宣称已经实现完整自定义。

零新增预算是持续约束：不因皮肤系统引入付费托管、CDN、域名或存储。商城与管理员面板重做由后续阶段共同规划；优先复用公开 GitHub 仓库、版本化 Release 附件和现有免费能力，不能把隐私配置发布到公共目录。

## 已完成的兼容基础

### R0：边界与威胁模型

已明确基础组件由宿主维护、管理后台排除、作者代码默认不执行、用户能够恢复内置皮肤，以及新增数据能力必须经过宿主授权。

### R1：公开组件和恢复入口

公开页面稳定钩子与组件注册表已建立。恢复布局、皮肤加载错误处理和权限管理由宿主可信界面提供，位于皮肤样式作用域之外。

### R2：声明式布局

schema v2 支持公开组件布局、桌面/平板/手机配置、本地覆盖、撤销/重做、导入导出及错误恢复。schema v1 视觉皮肤继续兼容。

### R3：开放皮肤与受控组件

皮肤包 schema v3 的客户端和服务端包校验、CSS 布局能力、声明式组件渲染、按组件权限审批与撤销、公开数据代理及有限宿主动作已接入。旧的 components.json schema v1 使用受限 JSON 节点，不运行作者 JavaScript 或 WebAssembly。宿主对每次动作重新校验。

自定义 UI 使用作者定义的节点和 CSS，不要求从固定宿主控件目录里选布局。宿主控件只是可以嵌入的可选可信功能块；页面交互按组件权限连接到有限、逐项校验的现有 TeamSpeak 功能。

### R3.1：扩展声明式交互（进行中）

- components.json schema v3 兼容 schema v1/v2，同时扩大节点/深度/列表上限，并增加键盘、指针、上下文菜单和拖放交互事件。
- 新增自己的麦克风/扬声器、音量、离开状态、悄悄话、断开连接和屏幕共享等宿主动作及逐项权限；皮肤只调用现有 WebSpeak 流程。
- 新增音频、悄悄话和屏幕共享的公开状态数据，不向组件提供私有 SDK 对象、地址、原始音频或屏幕流。
- 被动 focus/blur/hover/drag-start/drag-over 只能更新本地 UI 状态；触发宿主动作需要明确用户操作，输入/change 仍不能触发连接、切房或消息发送。
- 已获准并实际查看指定服务器前两个语音频道；麦克风全程关闭。只把左侧服务器栏/频道树、中心聊天、右侧成员栏和左下语音控制卡作为 KOOK 语音工作区参考，不记录房间标识、成员名单或聊天内容。详细观察记录见[KOOK 语音界面参考](./KOOK_VOICE_REFERENCE.zh-CN.md)。
- 频道树中的已加入语音频道会缩进显示成员项；底部语音卡集中显示频道、连接质量、离开、屏幕共享及音频控件。加入语音后中心聊天和右侧成员区仍可见。观察结束后已断开并关闭质量反馈提示；未发消息、未开启麦克风/摄像头，也未使用管理员功能。
- KAAK 示例现可在频道列表项下受限重复显示对应频道成员；该嵌套列表必须同时获准 `session.members.read`，并由宿主限制单组件实际渲染节点总量，避免多层重复造成界面膨胀。

### R3.2：受限作者逻辑运行时（有界 Wasm 已开放，持续审查中）

- 现有 JavaScript Worker 因缺少硬内存配额继续关闭；Wasmi 解释器用独立 Worker、解释器内存上限、扩展燃料上限和超时终止运行非可信 Wasm。
- 当前增量加入 `env.ui_emit_json`：单次运行最多输出一次、不超过 256 KiB 的 UTF-8 UI 数据，和组件包大小限制一致。宿主只接收有界 JSON，不执行 HTML/JS；TeamSpeak 动作仅通过 schema v6 受限动作效果申请，并由 WebClient 的独立宿主桥校验。
- 已实现严格 UTF-8 大小、JSON 与 schema v3/v4/v5/v6 输出校验，以及供 `SkinPluginOutlet` 使用的合并入口；schema v4 可生成标准 HTML/SVG 元素、普通属性、包内图片，并使用作用域隔离的 CSS；schema v5 额外携带有界标量状态和命名事件回调，schema v6 可附带单个宿主动作效果。自定义标签渲染为惰性占位 `div`，不实例化页面中可能注册的 Web Component。
- Wasm 有界输入协议新增 `env.ui_input_read`：每次运行最多读取一次、最多 64 KiB 的 JSON，包含插件本地标量状态、单个安全事件和按权限投影的公开数据快照（快照最多 48 KiB）。频道、成员、聊天、收藏/历史、音频、悄悄话、屏幕共享数据只输出清单声明权限对应的字段；连接地址、凭据、SDK 对象与未知字段不会从公开数据投影进入 guest。UI 事件只在浏览器 `isTrusted` 事件触发时由宿主组件发出；DOM/Event 对象不跨边界，只传事件名、组件/处理器 ID，以及受限的键盘字段。只有清单声明并经用户批准 `ui.input.read` 后，文本框/选择框值和勾选状态才会进入 guest；未授权时仅传事件元数据。生成的密码、文件和隐藏输入始终拒绝；输入值与状态还会二次限长验证。协议不含“trusted”自报字段，作者代码不能把字段伪装成宿主授权。
- Wasm UI 循环现用于生产 v4 插件：初始渲染、可信 UI 回调、授权数据变化均拆成逐次 Worker 调用；每次回调按先后顺序执行、最多排队 8 项。调用前重新检查回调 ID 与上次生成的 UI 一致，输入状态键只能来自该组件声明，输出再次经过 schema 4/5/6 校验。关闭时终止当前 Worker、清空等待队列。宿主动作只能跟随可信 UI 回调，不会从初始渲染或数据刷新触发。
- `SkinRuntimePlugin` 已接入权限化数据投影和首版宿主动作桥：插件需通过摘要绑定授权后才能运行；每次调用只收到清单允许的、经字段白名单筛选的数据副本。数据变化会在 100 ms 合并窗口后触发下一次独立调用。动作请求只接受 schema v6 单个宿主动作效果，且必须来自可信 UI 事件触发的同一轮 Wasm 调用；宿主再按插件声明权限和现有会话状态校验。受限 Wasm 已在生产构建开放；插件商城、widget 布局和独立安全审查仍未完成。
- 该动作桥是有界原型，不代表浏览器瞬时用户激活可跨越异步 Wasm 执行。动态 UI 可使用经 `voice.screenShare.control` 权限门控的 `voice.screen-share-start` 宿主按钮，在可信点击处理器内直接调用屏幕采集入口；运行时动作桥现拒绝 `voice.startScreenShare`，避免异步 Wasm 调用丢失浏览器激活。仍需在支持的浏览器中端到端验证按钮、授权和系统选择器行为；后续还需完成插件布局与安装管理，并评估不同浏览器的资源和事件边界。
- v4 现可支持作者用 Wasm 逻辑、通用安全节点树与包内 CSS 创建公开客户端界面；“完整插件平台”仍未完成。JavaScript 执行、专用安装/布局管理体验、商城、跨浏览器端到端验证和独立安全审查仍是后续工作。

### R3.3：自定义插件运行时（生产路径已接入，安全验收未完成）

授权、摘要校验、Wasm 生命周期、生成 UI 渲染、插件 CSS、权限化数据投影、首版宿主动作桥和 worker 资源治理已连到 WebClient，并通过本仓库 612 项测试、服务端构建和 Web 生产构建。生产路径只运行有界 Wasm；JavaScript 插件继续关闭。该运行时已能表达作者自定义的标准 HTML/SVG 节点树、包内 CSS、本地状态和受权限限制的 TeamSpeak 动作，但跨浏览器端到端验证和独立安全审查尚未完成，因此不能称为已完成的全量插件平台。

- v4 包格式的首个节点已落地：客户端和服务端共用 `plugins.json` 描述校验器，校验插件 ID、版本、页面、模式、权限、入口/样式/素材路径与重复 surface；客户端分开缓存插件文件，服务端校验文件存在和大小，并对文本入口/样式验证 UTF-8。
- 新增插件本地授权的安全基础：SHA-256 摘要绑定插件描述和所有声明文件，授权记录同时绑定皮肤/插件版本、API 版本、摘要与权限策略版本。任一代码、样式、素材、挂载模式或权限变化都会使旧授权不匹配。摘要不是发布者签名，亦不证明包来源可信。
- v4 入口支持 `.js` 与 `.wasm`；客户端对 Wasm 做固定导入/导出 ABI 预检，并按 MIME 类型分别缓存。服务端登记接受有大小上限的 Wasm 二进制，不运行它。
- v4 Wasm 适配器已接入 WebClient 的本地授权 UI 和页面生命周期。用户授权前不会创建 Worker；授权绑定皮肤版本、插件描述、入口、样式、素材及权限策略摘要。页面切换会关闭插件循环，撤销、运行失败或卸载会终止 Worker、移除插件样式和对象 URL，并恢复宿主页面。
- 已将有界 UI 循环接到生成节点树：Wasm 输出通过 schema 校验后由宿主渲染，不执行 HTML；只接收可信浏览器事件，组件状态和输入值继续限长。插件模式从 v4 描述继承，节点与 CSS 按插件 ID 隔离。插件 CSS 仅在明确授权且有有效输出后加载，并仅能引用全局皮肤资源和该插件自己的资源。
- 当前宿主只支持 Wasm 插件、`ui.surface.replace`、受限只读数据权限、可选的 `ui.input.read`，以及由现有权限表覆盖的 TeamSpeak 动作。数据投影不包含 TeamSpeak 地址、凭据或内部 SDK 对象；插件读取自己输入控件中的值必须单独声明 `ui.input.read`，而批准提示会说明浏览器自动填入的值也可能被读取。动作只能作为可信 UI 事件同轮 Wasm 输出中的单个效果提出，宿主再复核插件权限、当前批准状态、动作参数和会话可用性。JavaScript 插件与未实现的控制权限会显示为未支持状态，不会执行。
- 插件访问弹窗支持逐页批准、暂不启用、查看/撤销本皮肤的全部授权，并为 surface 提供切回标准界面和恢复内置皮肤入口。授权摘要或插件文件校验失败时关闭运行，不执行代码。
- 继续新增 opt-in 的插件协议，不给旧 v1/v2/v3 包追溯增加代码执行能力；同一皮肤可将界面分成多个独立、可排序、可显示/隐藏、可单独授权和回退的插件。
- Wasm 插件输出不再经过 v3 的固定标签、属性和数据绑定注册表：可生成标准 HTML/SVG 标签与普通属性，使用插件专属 CSS、图片、有限本地状态和命名事件回调；渲染由宿主创建，危险标签/属性、外部资源和自定义 Web Component 行为被拒绝或惰性替换。读取哪些公开数据及请求哪些 TeamSpeak 动作仍由 manifest 权限表限制；宿主控件目录只是可选的可信原生组件。
- v4 每个插件现有独立稳定的可编辑布局根，插件容器与插件根使用 Grid，使既有每皮肤、每设备布局编辑器可以分层调整插件整体和内部节点的顺序、位置、尺寸、显隐及安全外观；覆盖保存在本地宿主状态。widget 的可选 `mount` 字段现在可选择与页面匹配的公开宿主槽位；旧包未声明时继续挂在页面级插件宿主，surface 不能声明槽位。插件 ID、组件 ID 与布局根使用无碰撞标识。CSS/插件沙箱边界保持独立。
- 插件对 TeamSpeak 的读取和操作经明确列举的权限、脱敏投影和宿主能力桥接；命令总由宿主校验参数、当前会话和权限。双击等事件只改变插件化界面的触发方式，不更改 TeamSpeak 协议，也不影响未启用该插件的其他皮肤。
- 沙箱架构已选择为有界 Wasm 解释器运行于可终止的独立 Worker。此前 iframe 可通过自身导航外带获批数据，因此否决在有 DOM 的 iframe 中直接执行作者 JavaScript；JS Worker 因缺少硬内存配额仍不进入生产。此决定及触发原因保留在下方问题记录中。
- 已有 JavaScript 安全原型把作者代码放在没有 DOM/导航上下文的 data Worker 中；由于 JS Worker 没有硬内存上限，它仍不在生产执行。v4 Wasm 已通过有界解释器、通用节点树/CSS、命名事件回调和生产页面生命周期满足作者自定义界面的基础需求；后续重点是压测、跨浏览器验证和独立审查，不退回固定原生控件目录。
- 生产 Wasm UI 输出支持 schema v3/v4/v5/v6：v4 提供标准 HTML/SVG、普通属性和包内图片；v5 增加安全事件名到作者处理器 ID 的映射与本地状态；v6 可在事件触发的同轮输出中提出一个经插件权限校验的宿主动作。节点/组件/属性/文本仍有硬上限，危险加载、导航、脚本和事件属性会被拒绝。要求瞬时浏览器用户激活的能力仍须由可信宿主控件提供，并在真实浏览器验证。
- 插件生命周期已有批准前不加载、版本/内容变化重新确认、页面切换关闭、撤销销毁、超时/输出限额、错误恢复和旧包兼容；读取权限覆盖当前登记的数据类别，动作只允许现有 permission/action 表内能力。仍需做资源耗尽压测、跨浏览器端到端测试和独立安全审查；商城和专用插件管理体验留到管理员面板重做阶段。
- 复核零新增预算约束：插件及本地素材随皮肤包分发，不依赖 CDN、外部脚本托管或付费沙箱服务。

#### R3.3 问题记录

- 首个 v4 沙箱候选把 opaque-origin iframe 当成了“无网络”边界。复核浏览器规则发现沙箱 frame 仍有自己的文档和 URL 导航能力，`allow-top-navigation` 仅控制顶层页面；当前 MDN browser-compat-data 也没有 `navigate-to` 指令条目。因而 `connect-src 'none'`、禁用表单/弹窗和 CSP 元标签不足以证明获批数据不会通过 frame 导航外传。否决 iframe 直接执行作者 JS 的方案；JS Worker 仍因缺少硬内存上限保持生产关闭。之后改用有界 Wasm 解释器承载作者逻辑，并由可信宿主创建/校验通用自定义 UI 树与 CSS。
- Wasm UI 输出原先经过扩展校验后又送入 v3 固定标签/属性解析器，导致打开节点协议时整份扩展 UI 被悄悄丢弃。现改为分别校验基础皮肤和生成输出，只在组件 ID 不冲突且合并数量有界时组合，并额外把自定义标签渲染为惰性 `div`；生产 WebClient 已通过 v4 宿主渲染此输出。
- 运行时 UI 宿主最初将 `components: []` 占位文档交给要求至少一个组件的皮肤解析器，导致只有运行时插件的界面不会进入合并渲染路径。现仅在存在动态输出时把该内部空占位识别为 v3 容器；普通导入文档仍要求有效组件。
- 动态输出曾受 16 KiB 与展示标签/属性双重限制，复杂语音工作区难以由作者节点表达。现把单次输出提高到与组件包一致的 256 KiB，并接受普通标准 HTML/SVG 名称和普通属性；脚本、嵌入浏览器、外部资源/导航、事件属性及行内 CSS 仍通过明确拒绝列表保持隔离，样式走已隔离的插件 CSS。需要继续做浏览器端到端安全审查与结构上限压测。
- 一次性 Wasm 运行先前没有宿主发回本地界面状态或交互事件的入口。现增加每次调用只读一次、64 KiB 封顶的 `ui_input_read`、输出 schema v5 命名回调和生产 UI 重跑循环；宿主事件只传安全字段，不信任作者可伪造的“用户手势”标记。WebClient 摘要授权、页面生命周期、生成 UI 渲染、插件 CSS 装载、权限化只读数据投影及全局资源治理均已接入。现有首版动作桥允许同一可信事件触发的 Wasm 调用提出一个宿主动作；运行时插件整体及其节点现可本地排序。仍需真实浏览器验证瞬时手势行为并完成独立安全审查。
- 初次接入时，v4 surface 授权 UI 曾只列出权限却无法控制真实运行；循环关闭也没有联动移除 style 节点和对象 URL。现将授权状态绑定到实际启动路径，并在撤销、换页、失败、卸载时统一清理；v3 与 v4 对同一页声明 surface 时在导入阶段拒绝，避免两个整页 UI 互相覆盖。
- 运行时输入事件此前会默认把插件输入框的值发回 Wasm，清单没有独立同意项。现增加 `ui.input.read` opt-in；未批准时只传事件元数据，文本与勾选值不跨边界。授权 UI 显示权限用途，并提示浏览器自动填充值也可能暴露给插件；密码、文件、隐藏字段仍被拒绝。

### R3.4：声明式自定义节点布局编辑（已实施）

- 发现本地布局编辑器只登记了 WebSpeak 静态组件；皮肤 `components.json` 中自定义元素能用 CSS 排版，但不能由用户逐项移动、改尺寸或隐藏。
- 为每个自定义组件根和每个实际 DOM 节点生成带 page/component 的动态布局 ID，接入现有每皮肤、每设备的本地覆盖、撤销/重做、导入导出和恢复流程。
- 修复 v4 插件组件此前因布局 ID 包含插件和组件两层身份、未被动态注册器识别而无法编辑的问题；使用长度有界的组合标识后，插件布局根、组件根与子节点都能复用同一套本地覆盖。
- 显式 `part` 名称用于保持关键节点覆盖稳定；未命名节点采用组件树路径，树结构调整可能改变对应覆盖。声明式可操作节点仍按至少 44 px 触控目标进行校验。
- 本节点扩展的是已授权渲染的皮肤 UI；v4 插件布局根、组件根与节点现复用本地位置、顺序、尺寸和显隐编辑器。专用管理界面及独立安全审查仍未完成。

### R3.5：插件语义挂载槽位（已实施首版）

- `plugins.json` 为 widget 增加可选 `mount`；共享解析器按公开页面校验槽位，surface 继续直接组成页面，不接受 mount。未声明 mount 的旧包继续挂在页面级插件宿主。
- WebClient 在首页头部/内容/页脚，以及语音服务器栏、工作区头部、语音活动、聊天、频道成员面板、音频 dock、移动导航和全局浮层提供稳定锚点。插件根由固定槽位映射挂入；不能指定任意 CSS selector 或管理员页面。
- 插件 mount 字段纳入 SHA-256 授权摘要，避免修改挂载位置沿用旧批准。插件 CSS 和本地布局覆盖仍控制实际外观、尺寸、排序和隐藏。
- 发现并记录的问题：挂载锚点会随首页/语音页切换、surface 替换和连接模式条件渲染而暂时消失；宿主须在 DOM 更新后重新查询锚点，缺失时回退，防止插件被 Teleport 到脱离页面的旧节点而看似丢失。尚需补充真实浏览器切页与 surface 覆盖验证。

### R3.6：插件运行资源治理（已实施首版）

- WebClient 对所有运行时插件共用 FIFO Wasm worker 管理器：同时执行最多 2 个任务，等待队列最多 64 项，最长等待 120 秒。这样单次解释器上限不再被最多 64 个插件无界并发叠加。
- 切页、撤权或宿主卸载时会取消排队任务；活动任务沿用原有 worker 终止流程。队列满或等待超时会以明确的运行错误停止该插件，不扩大权限或绕过执行限制。
- 为队列顺序、容量、取消、重复释放和超时补充了单元测试。Wasm 已在生产构建开放；该节点完善了运行资源边界，但不代表独立安全审查已完成。
- 当前授权页中的“发现”路由展示了陪玩匹配、店铺列表、排行榜等运营内容；这些页面明确排除在 KOOK 语音客户端复刻范围之外。

### R3.7：完整 surface 的状态和表单交互（已实施首批）

- 复刻样例暴露了 v3 声明式界面的两个实际缺口：条件只能和静态常量比较，不能把用户选中的行与重复数据关联；宿主动作也被禁止绑定到提交后的 `change`，导致自定义滑杆等控件只能显示、无法驱动 TeamSpeak。
- 扩展 schema v3 条件，使其可将本地状态与权限化重复项字段比较，并可针对有读取权限的公开集合声明空态。v1/v2 不接受这些新增字段，既有包继续保持原边界。
- 允许 `change` 上的宿主动作，保留 `input` 仅更新本地状态的规则；滑杆松手、选择器提交等已提交交互可以调用权限内动作。WebClient 音量入口接受浏览器范围控件提交的数值字符串并在宿主端校验和夹限。
- Harbor Voice 首次把聊天消息/输入框、麦克风/扬声器/音量/断开、悄悄话和频道选中态改为皮肤自有结构与 CSS；单击仅选中，双击复用现有 TeamSpeak 切换流程。屏幕采集和实时视频仍由可信宿主控件执行，皮肤可重排并完全换肤。
- 已为条件解析、集合空态、表单事件及 Harbor `.wskin` 结构补回归测试；仍需在真实语音会话中验证控件行为和桌面/移动视觉效果。

### R4：整页皮肤界面和宿主控件组合（核心路径已接入，完整验收待完成）

#### R4 问题记录

- 初版 surface 可以在没有任何数据/API 权限时直接替换页面，安装皮肤即可能显示仿制界面。现要求 surface 额外申请 `ui.surface.replace`，用户批准前继续显示 WebSpeak 原页面，并覆盖拒绝与撤销路径。
