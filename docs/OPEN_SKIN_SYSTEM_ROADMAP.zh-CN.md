# 更开放的皮肤系统路线图

皮肤只作用于 WebSpeak 的公开连接首页和语音工作区。完成态要求作者能把公开界面几乎完整地做成自己的应用：所有公开组件都能重新排列、换皮、显隐或由作者自定义组件替代；作者可为自定义界面编写布局、样式和本地交互逻辑，不受固定宿主控件目录限制。TeamSpeak 连接、聊天、频道和音频行为仍由宿主能力层执行，管理后台、管理 API、演示设施及 KOOK 运营/广告页面不在范围内。

现有 v1/v2/v3 是兼容基础，不是“万物皆插件”的完成态。v3 的标签/属性、数据路径和宿主动作均为有限白名单；Wasm UI 输出现已接入开发构建的生命周期，但生产执行仍关闭。不得用“支持自定义节点”或“支持整页 surface”宣称已经实现完整自定义。

零新增预算是持续约束：不因皮肤系统引入付费托管、CDN、域名或存储。商城与管理员面板重做由后续阶段共同规划；优先复用公开 GitHub 仓库、版本化 Release 附件和现有免费能力，不能把隐私配置发布到公共目录。

## 已完成的兼容基础

### R0：边界与威胁模型

已明确基础组件由宿主维护、管理后台排除、作者代码默认不执行、用户能够恢复内置皮肤，以及新增数据能力必须经过宿主授权。

### R1：公开组件和恢复入口

公开页面稳定钩子与组件注册表已建立。恢复布局、皮肤加载错误处理和权限管理由宿主可信界面提供，位于皮肤样式作用域之外。

### R2：声明式布局

schema v2 支持公开组件布局、桌面/平板/手机配置、本地覆盖、撤销/重做、导入导出及错误恢复。schema v1 视觉皮肤继续兼容。

### R3：开放皮肤与受控组件

皮肤包 schema v3 的客户端和服务端包校验、CSS 布局能力、声明式组件渲染、按组件权限审批与撤销、公开数据代理及有限宿主动作已接入。旧的 components.json schema v1 使用受限 JSON 节点，不运行作者 JavaScript 或 WebAssembly。宿主对每次动作重新校验。

自定义 UI 使用作者定义的节点和 CSS，不要求从固定宿主控件目录里选布局。宿主控件只是可以嵌入的可选可信功能块；页面交互按组件权限连接到有限、逐项校验的现有 TeamSpeak 功能。

### R3.1：扩展声明式交互（进行中）

- components.json schema v3 兼容 schema v1/v2，同时扩大节点/深度/列表上限，并增加键盘、指针、上下文菜单和拖放交互事件。
- 新增自己的麦克风/扬声器、音量、离开状态、悄悄话、断开连接和屏幕共享等宿主动作及逐项权限；皮肤只调用现有 WebSpeak 流程。
- 新增音频、悄悄话和屏幕共享的公开状态数据，不向组件提供私有 SDK 对象、地址、原始音频或屏幕流。
- 被动 focus/blur/hover/drag-start/drag-over 只能更新本地 UI 状态；触发宿主动作需要明确用户操作，输入/change 仍不能触发连接、切房或消息发送。
- 已获准并实际查看指定服务器前两个语音频道；麦克风全程关闭。只把左侧服务器栏/频道树、中心聊天、右侧成员栏和左下语音控制卡作为 KOOK 语音工作区参考，不记录房间标识、成员名单或聊天内容。详细观察记录见[KOOK 语音界面参考](./KOOK_VOICE_REFERENCE.zh-CN.md)。
- 频道树中的已加入语音频道会缩进显示成员项；底部语音卡集中显示频道、连接质量、离开、屏幕共享及音频控件。加入语音后中心聊天和右侧成员区仍可见。观察结束后已断开并关闭质量反馈提示；未发消息、未开启麦克风/摄像头，也未使用管理员功能。
- KAAK 示例现可在频道列表项下受限重复显示对应频道成员；该嵌套列表必须同时获准 `session.members.read`，并由宿主限制单组件实际渲染节点总量，避免多层重复造成界面膨胀。

### R3.2：受限作者逻辑运行时（原型，生产关闭）

- 现有 JavaScript Worker 因缺少硬内存配额继续关闭；Wasmi 原型用独立 Worker、解释器内存上限、扩展燃料上限和超时终止运行非可信 Wasm。
- 当前增量加入 `env.ui_emit_json`：单次运行最多输出一次、不超过 16 KiB 的 UTF-8 UI 数据。宿主只接收有界字符串，不执行 HTML/JS；TeamSpeak 动作仅通过 schema v6 受限动作效果申请，并由 WebClient 的独立宿主桥校验。
- 已实现严格 UTF-8 大小、JSON 与 schema v3/v4/v5/v6 输出校验，以及供 `SkinPluginOutlet` 使用的合并入口；schema v4 可生成安全 HTML/SVG、ARIA/data 属性与包内图片，schema v5 额外携带有界标量状态和命名事件回调，schema v6 可附带单个宿主动作效果。自定义标签渲染为惰性占位 `div`，不实例化页面中可能注册的 Web Component。
- Wasm 有界输入协议新增 `env.ui_input_read`：每次运行最多读取一次、最多 64 KiB 的 JSON，包含插件本地标量状态、单个安全事件和按权限投影的公开数据快照（快照最多 48 KiB）。频道、成员、聊天、收藏/历史、音频、悄悄话、屏幕共享数据只输出清单声明权限对应的字段；地址、凭据、SDK 对象与未知字段不会进入 guest。UI 事件只在浏览器 `isTrusted` 事件触发时由宿主组件发出；DOM/Event 对象不跨边界，只传事件名、组件/处理器 ID，以及受限的键盘或输入值字段。生成的密码、文件和隐藏输入会拒绝；输入值与状态还会二次限长验证。协议不含“trusted”自报字段，作者代码不能把字段伪装成宿主授权。
- 新增开发原型 `skin-extension-wasm-ui-loop`，把初始渲染、可信 UI 回调、授权数据变化建模为逐次 Wasm Worker 调用：每次回调按先后顺序执行、最多排队 8 项；调用前重新检查回调 ID 与上次生成的 UI 一致，输入状态键只能来自该组件声明；输出再次经过 schema 4/5/6 校验。关闭时终止当前 Worker、清空等待队列。宿主动作只能跟随可信 UI 回调，不会从初始渲染或数据刷新触发。
- `SkinRuntimePlugin` 已接入权限化数据投影和首版宿主动作桥：插件需通过摘要绑定授权后才能运行；每次调用只收到清单允许的、经字段白名单筛选的数据副本。数据变化会在 100 ms 合并窗口后触发下一次独立调用。动作请求只接受 schema v6 单个宿主动作效果，且必须来自可信 UI 事件触发的同一轮 Wasm 调用；宿主再按插件声明权限和现有会话状态校验。Wasm 仍为开发原型，生产开关关闭；插件商城、widget 布局和安全审查未完成。
- 该动作桥是有界原型，不代表浏览器瞬时用户激活可跨越异步 Wasm 执行：屏幕共享等要求瞬时手势的 API 仍需真实浏览器验证。后续需完成插件布局与安装管理、端到端验证，并评估不同浏览器的资源和事件边界。
- 这是一次性输出的受限原型，不构成完整插件运行时。生产开关关闭；后续须更换为有版本、权限、事件、生命周期和资源治理的插件协议，并做端到端与独立安全审查。

### R3.3：完整自定义插件运行时（未完成，优先阶段）

当前已完成仅限开发构建的接入节点：授权、摘要校验、Wasm 生命周期、生成 UI 渲染、插件 CSS、权限化数据投影和首版宿主动作桥已经连到 WebClient。它仍是安全原型，生产构建保持关闭，不能视为完整或经安全审查的插件运行时。

- v4 包格式的首个节点已落地：客户端和服务端共用 `plugins.json` 描述校验器，校验插件 ID、版本、页面、模式、权限、入口/样式/素材路径与重复 surface；客户端分开缓存插件文件，服务端校验文件存在和大小，并对文本入口/样式验证 UTF-8。
- 新增插件本地授权的安全基础：SHA-256 摘要绑定插件描述和所有声明文件，授权记录同时绑定皮肤/插件版本、API 版本、摘要与权限策略版本。任一代码、样式、素材、挂载模式或权限变化都会使旧授权不匹配。摘要不是发布者签名，亦不证明包来源可信。
- v4 入口支持 `.js` 与 `.wasm`；客户端对 Wasm 做固定导入/导出 ABI 预检，并按 MIME 类型分别缓存。服务端登记接受有大小上限的 Wasm 二进制，不运行它。
- 开发态 v4 Wasm 适配器已接入 WebClient 的本地授权 UI 和页面生命周期。用户授权前不会创建 Worker；授权绑定皮肤版本、插件描述、入口、样式、素材及权限策略摘要。页面切换会关闭插件循环，撤销、运行失败或卸载会终止 Worker、移除插件样式和对象 URL，并恢复宿主页面。
- 已将有界 UI 循环接到生成节点树：Wasm 输出通过 schema 校验后由宿主渲染，不执行 HTML；只接收可信浏览器事件，组件状态和输入值继续限长。插件模式从 v4 描述继承，节点与 CSS 按插件 ID 隔离。插件 CSS 仅在明确授权且有有效输出后加载，并仅能引用全局皮肤资源和该插件自己的资源。
- 当前开发宿主只支持 Wasm 插件、`ui.surface.replace`、受限只读数据权限，以及由现有权限表覆盖的 TeamSpeak 动作。数据投影不包含 TeamSpeak 地址、凭据或内部 SDK 对象；动作只能作为可信 UI 事件同轮 Wasm 输出中的单个效果提出，宿主再复核插件权限、当前批准状态、动作参数和会话可用性。JavaScript 插件与未实现的控制权限会显示为未支持状态，不会执行；生产构建也通过 `import.meta.env.DEV` 保持运行时关闭。
- 插件访问弹窗支持逐页批准、暂不启用、查看/撤销本皮肤的全部授权，并为 surface 提供切回标准界面和恢复内置皮肤入口。授权摘要或插件文件校验失败时关闭运行，不执行代码。
- 继续新增 opt-in 的插件协议，不给旧 v1/v2/v3 包追溯增加代码执行能力；同一皮肤可将界面分成多个独立、可排序、可显示/隐藏、可单独授权和回退的插件。
- 插件可自定义公开界面的 DOM 结构、CSS、组件状态和普通 UI 事件，不局限于当前标签、属性、数据字段和固定动作表。宿主控件目录变成可选的兼容原生组件。
- v4 每个插件现有独立稳定的可编辑布局根，插件容器与插件根使用 Grid，使既有每皮肤、每设备布局编辑器可以分层调整插件整体和内部节点的顺序、位置、尺寸、显隐及安全外观；覆盖保存在本地宿主状态。仍缺少作者声明的宿主挂载槽位和默认布局字段；插件 ID、组件 ID 与布局根使用无碰撞标识。CSS/插件沙箱边界保持独立。
- 插件对 TeamSpeak 的读取和操作经明确列举的权限、脱敏投影和宿主能力桥接；命令总由宿主校验参数、当前会话和权限。双击等事件只改变插件化界面的触发方式，不更改 TeamSpeak 协议，也不影响未启用该插件的其他皮肤。
- 沙箱架构还未选定。opaque-origin iframe 可以隔离父页面 DOM 和存储，但不等于网络隔离：浏览器仍允许 frame 自己导航，`sandbox` 主要阻止顶层导航；CSP `navigate-to` 也不能作为跨浏览器阻断保证。若 iframe 同时持有获批的会话数据，插件可尝试把数据编码进自己的导航 URL。详见 R3.3 问题记录。不得因此把任意 JS 放进有浏览 DOM 的 iframe。
- 已有安全原型把作者 JavaScript 放在没有 DOM/导航上下文的 data Worker 中，由 opaque-origin iframe 只负责消息桥；Worker CSP 可限制常规网络请求，但没有硬内存上限，仍保持生产关闭。下一版运行时必须同时保留完整自定义 UI 能力和确定的计算/内存边界：优先评估有界解释器 + 宿主创建的通用自定义节点树/CSS；不能以牺牲 DOM/事件自定义为理由退回固定原生控件目录。
- 新增 Wasm UI 输出 schema v4/v5/v6 原型：v4 提供常见安全 HTML/SVG、`data-*`/`aria-*` 和惰性自定义元素占位；v5 增加安全事件名到作者处理器 ID 的映射与本地状态；v6 可在事件触发的同轮输出中提出一个经插件权限校验的宿主动作。节点/组件/属性/文本仍有硬上限，危险加载、导航、脚本和事件属性会被拒绝。动作桥尚未做生产安全审查；要求瞬时浏览器用户激活的能力仍需真实浏览器验证。
- 插件生命周期的开发态路径已有批准前不加载、版本/内容变化重新确认、页面切换关闭、撤销销毁、超时/输出限额、错误恢复和旧包兼容。生产启用仍需完成更广的数据与动作权限、可信事件票据、资源耗尽和跨浏览器测试、独立安全审查。
- 复核零新增预算约束：插件及本地素材随皮肤包分发，不依赖 CDN、外部脚本托管或付费沙箱服务。

#### R3.3 问题记录

- 首个 v4 沙箱候选把 opaque-origin iframe 当成了“无网络”边界。复核浏览器规则发现沙箱 frame 仍有自己的文档和 URL 导航能力，`allow-top-navigation` 仅控制顶层页面；当前 MDN browser-compat-data 也没有 `navigate-to` 指令条目。因而 `connect-src 'none'`、禁用表单/弹窗和 CSP 元标签不足以证明获批数据不会通过 frame 导航外传。否决 iframe 直接执行作者 JS 的方案；保留现有只运行于无 DOM Worker 的原型，但 JS 内存无硬上限，继续关闭生产执行。下一步必须通过可计量执行环境承载作者逻辑，并由可信宿主创建/校验通用自定义 UI 树与 CSS，再验证事件到 TeamSpeak 能力的桥接。
- Wasm UI 输出原先经过扩展校验后又送入 v3 固定标签/属性解析器，导致打开节点协议时整份扩展 UI 被悄悄丢弃。现改为分别校验基础皮肤和生成输出，只在组件 ID 不冲突且合并数量有界时组合，并额外把自定义标签渲染为惰性 `div`；此输出现在由开发态 v4 WebClient 宿主渲染。生产仍关闭。
- 一次性 Wasm 运行先前没有宿主发回本地界面状态或交互事件的入口。现增加每次调用只读一次、64 KiB 封顶的 `ui_input_read`、输出 schema v5 命名回调，以及开发态有界 UI 重跑控制器；宿主事件只传安全字段，不信任作者可伪造的“用户手势”标记。原先缺少的 WebClient 摘要授权、页面生命周期、生成 UI 渲染、插件 CSS 装载及权限化只读数据投影已由本节点接入。现有首版动作桥允许同一可信事件触发的 Wasm 调用提出一个宿主动作；运行时插件整体及其节点现可本地排序，余下缺口是显式挂载槽位、浏览器瞬时手势验证和生产级安全审查。
- 初次接入时，v4 surface 授权 UI 曾只列出权限却无法控制真实运行；循环关闭也没有联动移除 style 节点和对象 URL。现将授权状态绑定到实际启动路径，并在撤销、换页、失败、卸载时统一清理；v3 与 v4 对同一页声明 surface 时在导入阶段拒绝，避免两个整页 UI 互相覆盖。

### R3.4：声明式自定义节点布局编辑（已实施）

- 发现本地布局编辑器只登记了 WebSpeak 静态组件；皮肤 `components.json` 中自定义元素能用 CSS 排版，但不能由用户逐项移动、改尺寸或隐藏。
- 为每个自定义组件根和每个实际 DOM 节点生成带 page/component 的动态布局 ID，接入现有每皮肤、每设备的本地覆盖、撤销/重做、导入导出和恢复流程。
- 修复 v4 插件组件此前因布局 ID 包含插件和组件两层身份、未被动态注册器识别而无法编辑的问题；使用长度有界的组合标识后，插件布局根、组件根与子节点都能复用同一套本地覆盖。显式挂载槽位仍属于 R3.3 后续节点。
- 显式 `part` 名称用于保持关键节点覆盖稳定；未命名节点采用组件树路径，树结构调整可能改变对应覆盖。声明式可操作节点仍按至少 44 px 触控目标进行校验。
- 本节点扩展的是已授权渲染的声明式皮肤 UI，不执行作者脚本；v4 插件布局根、组件根与节点现复用本地位置、顺序、尺寸和显隐编辑器。显式挂载槽位、专用管理界面和生产级沙箱仍未完成。

### R4：整页皮肤界面和宿主控件组合（进行中）

- components.json schema v2 引入、schema v3 继续支持 `mode: "surface"`，允许替换首页或语音工作区的完整可见页面；旧 schema v1/v2 继续兼容。
- 当前 v3 surface 用受限节点、受控 CSS、公开数据绑定及白名单动作构建布局，不运行作者代码；这是 R3.3 完成前的兼容能力，不满足完整插件自定义目标。
- 整页替换要求用户单独批准 `ui.surface.replace`；页面权限确认、撤销入口和恢复控件由宿主绘制。
- 可选宿主控件 ID 包括连接表单、皮肤/语言选择器、频道成员面板、语音成员卡、聊天、音频控制、屏幕共享、悄悄话、性能面板和退出控件。控件只在 WebSpeak 内执行，作者代码无法读取其私有状态；每个有状态控件每页仅可挂载一次。自定义声明式元素不受此注册表限制。
- 为完整定制常用服务器栏提供脱敏的收藏/历史列表与宿主切换动作；地址、密码和身份材料仍留在 WebSpeak 内。
- 页面权限确认、撤销入口和“返回标准界面”控件在皮肤 CSS 作用域之外。页面替换被拒绝或退出时，原生首页/语音工作区重新显示。
- 补充导入、旧包兼容、页面替换、权限拒绝/撤销、宿主控件及皮肤切换回归。
- 已提供 v3 首页/语音工作区 surface 样例及 KAAK 语音外观样例；它们验证现有格式，不代表插件系统目标已完成。KAAK 不引入发现、广告、陪玩、活动或商城页面。
- KOOK 参考皮肤只实现语音客户端体验；不复制运营、广告、陪玩、活动和商城页面。当前发现页确实把陪玩匹配、店铺卡片和推荐内容放在独立发现工作流中，这些都不纳入客户端复刻。只有能实际查看的公开/授权界面才作为视觉依据。

#### R4 问题记录

- 初版 surface 可以在没有任何数据/API 权限时直接替换页面，安装皮肤即可能显示仿制界面。现要求 surface 额外申请 `ui.surface.replace`，用户批准前继续显示 WebSpeak 原页面，并覆盖拒绝与撤销路径。
- surface 的“恢复内置皮肤”按钮误接到仅用于皮肤加载错误的回退函数，正常皮肤下点击无效。已改为明确切换到当前主题对应的内置皮肤，并增加授权/撤销回归。
- 初版自定义服务器栏只有收藏数据，缺少最近连接项。新增 `servers.quickList` 和宿主切换动作，使用不透明令牌，不下放目标地址或凭据。
- 收藏名/最近连接显示名有时会直接等于服务器地址；投影数据前增加地址匹配与泛化标签，避免通过“显示名”字段间接暴露连接目标。
- 已获准进入 KOOK 服务器前两个语音房间。结合可访问结构和截图确认：左侧为服务器轨道与频道树，中间继续显示当前文字频道聊天，右侧是在线/离线成员栏，左下连接卡显示频道、信号、离开、屏幕共享与音频控制；自己的语音成员项挂在频道行下。进入与切换通过再次点击频道完成，麦克风状态保持关闭。未发消息、未使用管理员功能，也未记录房间标识、成员名单或聊天内容。退出后语音质量反馈提示已关闭。陪玩店、活动通知、广告及其他运营页面不作为参考。
- 用户指出“有限自定义”与目标不符。核查确认当前 v3 仍固定标签/属性白名单、六种可重复数据集、模板插值和有限宿主动作；一次 Wasm 输出尚未接进生产 UI 生命周期。此处列为 R3.3 的首要差距，不以增加几个声明式动作或宿主控件替代完整插件运行时。
- 已确认 schema 支持 `dblclick`。KAAK 频道行现在只在双击时请求宿主加入频道；这属于单个皮肤包的界面映射，其他皮肤与 TeamSpeak 协议保持不变。
