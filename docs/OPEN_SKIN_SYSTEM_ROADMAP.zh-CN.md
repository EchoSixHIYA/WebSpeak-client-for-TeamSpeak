# 更开放的皮肤系统路线图

当前路线把皮肤能力限定在 WebSpeak 的公开连接首页、语音工作区和演示页。目标是让基础组件能自由安排、设定样式与显隐，并允许作者用声明式组件补充界面。管理员面板、管理 API 和语音服务运营页面都不纳入皮肤范围。

零新增预算是持续约束：不因皮肤系统引入付费托管、CDN、域名或存储。商城与管理员面板重做由后续阶段共同规划；优先复用公开 GitHub 仓库、版本化 Release 附件和现有免费能力，不能把隐私配置发布到公共目录。

## 已完成

### R0：边界与威胁模型

已明确基础组件由宿主维护、管理后台排除、作者代码默认不执行、用户能够恢复内置皮肤，以及新增数据能力必须经过宿主授权。

### R1：公开组件和恢复入口

公开页面稳定钩子与组件注册表已建立。恢复布局、皮肤加载错误处理和权限管理由宿主可信界面提供，位于皮肤样式作用域之外。

### R2：声明式布局

schema v2 支持公开组件布局、桌面/平板/手机配置、本地覆盖、撤销/重做、导入导出及错误恢复。schema v1 视觉皮肤继续兼容。

### R3：开放皮肤与受控组件

schema v3 的客户端和服务端包校验、CSS 布局能力、声明式组件渲染、按组件权限审批与撤销、公开数据代理及有限宿主动作已接入。自定义组件使用受限 JSON 节点，不运行作者 JavaScript 或 WebAssembly。只有经用户启用的组件才可读取明确列出的公开会话数据或提出宿主动作；宿主对每次动作重新校验。

当前白名单包括连接摘要、公开频道、可见成员、当前公开频道消息和脱敏收藏名称。宿主动作覆盖公开频道加入、已有收藏切换、当前频道聊天发送和组件本地状态更新。收藏服务器地址、密码、身份密钥、私聊、原始音频、屏幕流、管理 API、任意网络和浏览器存储均不提供。

CSS v3 可以完全改变公开页面布局、尺寸、排版和显隐，所以皮肤可能遮挡普通界面。宿主权限和恢复控件不受其 CSS 控制；实际皮肤仍要检查触屏、键盘、移动端及语音操作可达性。CSS 隔离不是恶意代码沙箱。

## 下一步

### R4：作者体验与兼容性

- 完成 Illusia 和 KAAK 示例的 v3 迁移，提供真实可导入的 .wskin 包和清楚的权限清单。
- 为组件数据绑定、重复列表、动作校验、用户拒绝与撤销补足自动化回归。
- 改善权限说明和皮肤开发文档；注明视觉预览限制、CSS 可隐藏普通 UI 的风险及恢复方式。
- 汇总公开语音界面的预览问题并修复；不扩展到无关业务代码。

### R5：皮肤商城与管理员面板重做时交付

- 商城目录、发现、安装、更新、回退、下架与撤销同管理员面板改造一起设计；后台本身保持不可皮肤化。
- 首选人工审查的静态清单和 Release 附件，列出来源、版本、许可证、包校验值和组件权限。
- 对目录不可用、版本冲突、撤销及离线场景提供可靠回退。
- 维持零新增服务费用；任何无法在现有免费资源内解决的规模问题，重新确认预算后再处理。
- 不默认加入评分、评论、付款、付费托管或第三方账号接入。

## 迁移和验收

- v1、v2 包继续按原有规则校验；只有明确声明 open-skin 的 v3 包才有 v3 CSS 与组件能力。
- 未知版本、字段、权限、节点、数据路径、动作和素材类型都拒绝导入。
- 每次将相关修改合并成一批统一运行验证，避免每个小节点重复跑全套构建。
- 验收桌面与移动视口、产品支持语言、键盘与触屏、焦点状态、语音/静音/退出和皮肤恢复路径。
- 管理端、运营页面、Android 计划及语音业务逻辑不因开放皮肤系统而扩展。
